Task 1

상권분석 VQA

매장 이미지 한 장을 보고 8개 업종 중 주된 업종 하나를 고르는 문제입니다. 음식 하나만 보고 판단하면 틀리기 쉬워서, 무엇을 주로 팔고 손님이 어떻게 이용하는지를 함께 봐야 합니다.

  • A한식
  • B양식
  • C일식
  • D중식
  • E카페
  • F베이커리
  • G주점
  • H동남아
Model
Qwen3-VL-8B-Instruct
추가 학습 없이 추론만, 단일 VLM 중심
Method
8-way TTA + 계층 판단

  • 생성된 문자 대신 A~H 토큰 점수를 사용

8-way 선택지 순환 TTA

VLM은 선택지의 내용과 상관없이 특정 위치의 문자를 더 자주 고르는 경향이 있습니다. 같은 이미지·같은 모델로 업종과 A~H의 매핑만 8번 돌려서 이 편향을 평균으로 지웠습니다.

1

선택지 순환

업종 ↔ A~H 매핑만 8번 회전시켜 8번 추론

2

업종 기준 역매핑

문자별 점수를 원래의 한식·양식… 순서로 되돌림

3

확률 평균

8번의 상대 점수를 산술평균하고, 1위를 base 라벨로 지정

확률 차이가 충분할 때만 계층적으로 보정

카페·베이커리·주점처럼 서로 헷갈리는 업종이 많아서, 먼저 큰 갈래를 정하고 그 안에서 고르게 했습니다. 갈래 간 확률 차이가 0.15보다 작으면 섣불리 바꾸지 않습니다.

STAGE 1 · 8회 평균 확률
R = A+B+C+D+H  vs  S = E+F+G음식점(한·양·일·중·동남아) vs 카페·베이커리·주점
|R − S| < 0.15

base 라벨 유지
차이가 작으면 TTA 결과를 그대로 사용

R > S · 음식점

As = A+C+D+H (아시아) vs W = B (서양)

As 우세 → A·C·D·H 중 최대
W 우세 → B 양식
S > R · 카페류

E·F·G 중 최대
카페, 베이커리, 주점 중에서 선택

프롬프트: 나열에서 규칙으로

초기

모델과 시점 위주

  • 모델·crop·multi-view 실험이 먼저, 프롬프트 분석은 뒤로 밀림
  • 선택지 설명은 단순 나열
  • 작은 물체 하나에 판단이 흔들림
  • 카페·베이커리·주점 혼동이 반복됨
최종

고민한 내용을 규칙으로

  • 먼저 주된 영업 형태를 판단
  • 음식점이면 서양 / 아시아로 나누고, 아시아면 한·일·중·동남아로 나눔
  • 단서 하나로 결정하지 않고 근거 2가지를 교차 확인
  • 근거가 충돌하면 주된 판매·이용 형태를 우선

Task 2

Reasoning Segmentation

이미지와 함께 “차가 갑자기 멈춰야 할 때 뒤차에 경고하려면 어떤 버튼을 누를까?” 같은 간접적인 질문이 주어집니다. 질문이 가리키는 대상을 추론으로 찾아 픽셀 단위 마스크로 분할하는 문제로, 평가는 Dice, 테스트 이미지는 200장입니다.

  1. STEP 1
    입력
    IMAGE + QUERY

    1000×1000 이미지와 영어로 된 질문

  2. STEP 2
    쿼리 유형 분류
    Qwen3-VL

    필요한 추론 방식에 따라 A~F 중 하나로 분류

  3. STEP 3
    유형별 프롬프트로 대상 찾기
    Qwen3-VL

    대상마다 bbox와 point를 JSON으로 출력, 여러 개면 모두

  4. STEP 4
    마스크 생성
    SAM 2.1

    bbox를 1.03배 넓히고 point와 함께 프롬프트로 사용

  5. STEP 5
    합치고 인코딩
    RLE → CSV

    대상별 마스크를 합쳐 RLE로 변환해 제출

Fail-safe. 유형 분류나 JSON 파싱이 실패하면 범용 프롬프트로 돌아가서 루프가 멈추지 않게 했습니다. 유형 분포와 fallback 비율은 200개를 돌 때마다 기록해 디버깅 근거로 썼습니다. 직전 버전 실행 로그 기준으로 200개 중 199개가 정상 처리됐고, 1개는 fallback으로 처리됐습니다.

점수 변화: 0.4724 → 0.513

이틀 동안 여섯 번 개선했습니다. 첫날은 모델 조합과 bbox 크기를 정했고, 둘째 날은 프롬프트와 출력 규칙을 다듬었습니다.

    첫날: 기반 고르기

    채택

    bbox 1.03배 확장

    Qwen이 준 bbox를 SAM에 넘기기 전에 조금 넓혔습니다. 1.0 / 1.05 / 1.10배를 비교했더니 1.05배 근처에서 점수가 꺾여서, 범위를 좁혀 다시 재보니 1.03배가 가장 좋았습니다. 이 설정으로 첫날 0.474를 기록했습니다.

    포기

    Visual CoT (Qwen 2개 연결)

    첫 번째 Qwen이 crop할 bbox와 reasoning을 만들고, 두 번째 Qwen이 원본과 crop 이미지, 앞의 reasoning을 함께 받아 최종 대상을 찾는 구조였습니다. 그런데 원래 잘 맞히던 문제까지 틀리기 시작했고, 원본 이미지를 빼거나 reasoning 전달을 생략해도 나아지지 않아 접었습니다.

    둘째 날: 쿼리 라우터

    질문마다 필요한 추론 방식이 달라서, 먼저 질문 유형을 분류하고 유형마다 다른 추론 지시를 붙였습니다. 막대는 직전 버전을 실행했을 때 200개 질문이 각 유형으로 분류된 개수입니다.
